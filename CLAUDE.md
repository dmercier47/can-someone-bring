# Can Someone Bring

Signup sheets for dinner parties and house parties, shared via a link in a Partiful invite.

- Read `SPEC.md` first: product flow, v1 scope, data model, build order.
- Stack: Next.js 15 (App Router) + TypeScript + Tailwind v4 + Supabase (hosted). Email: Supabase Auth sends through Resend SMTP from `hello@mail.cansomeonebring.com`; `RESEND_API_KEY` (sending-only, domain-scoped) is in Vercel + `.env.local` for future app emails.
- Database: SQL migrations in `supabase/migrations/` (append new numbered files, never edit applied ones). `npm run db:migrate` applies them, `npm run db:seed` resets the demo sheet at `/s/demo`. Both use `DATABASE_URL` from `.env.local` (see `.env.example`). No Docker/Supabase CLI.
- Security model: RLS on every table; the browser (anon/publishable key) gets no table access. Guest reads/writes go through server code (`src/lib/sheets.ts`, `src/app/s/[slug]/actions.ts`) using the secret key in `src/lib/supabase/admin.ts` (server-only). Never send `edit_token` or `guest_email` to the client except a guest's own token right after they claim. New Supabase projects don't auto-grant table privileges: add explicit `grant`s for new tables (see `0002_grants.sql`).
- **Mobile web first**: design every screen at 375px wide, then scale up. Inputs use 16px text (prevents iOS zoom), tap targets ≥ 44px, no hover-only UI, respect `env(safe-area-inset-*)`.
- Visual identity is "Bands" (see SPEC.md). Light only. Hedvig Letters Serif (display: headlines, category names, wordmark) + Hedvig Letters Sans (everything else). Both have ONE weight and `font-synthesis: none` is set: never use font-bold/semibold/extrabold; build hierarchy with size, serif vs sans, and ink vs muted. Big numbers use the sans (serif "11" reads as "ll").
- **Brand vibe (check every change against it)**: exclusive, hot-girl New York. Queer and alt-leaning: a Ridgewood dinner with candles and natural wine, Hell's Kitchen gays with a martini kit. Confident, in-the-know, a little camp, never trying too hard (mood reference: the party app Lettuce; keep our own identity, don't copy it). Exclusive in tone, never in friction: guests still claim in two taps with no account. Use specifics a host would really ask for (the good cheese, dirty martini olives, natural wine, tinned fish, a bouquet), not suburban-potluck items (folding chairs, chores, paper plates) or cringe filler ("the gossip", "a playlist with range"). Avoid slang that dates fast ("ate", "slay", "brat"), rainbow/pride clichés and stereotypes that punch down. When the user asks for something that pulls away from this, say so and suggest the on-vibe version.
- Avoid AI-UI tells: no emoji or unicode glyphs as icons (use `src/components/icons.tsx`), no boxes inside boxes (hairlines + tints instead), radius scale 12px / 20px / pill-for-actions only, no em dashes or filler copy ("Heads up", "Totally fine").
- Colors are tokens in `src/app/globals.css` (`bg-bg`, `text-ink`, `text-faint`, `border-hair`, `bg-pill`, `bg-cat-yellow`, `text-cat-muted`, …; tint classes via `CARD_BG` in `src/lib/colors.ts`); don't hardcode hex values in components.
- Stickers: use `<Sticker name="pie" />` (`src/components/Sticker.tsx`); add new keys in `src/lib/stickers.ts` and check the URL returns 200.
- Guests never create accounts. Hosts sign in with an emailed code (autofill-friendly) or the email's link.
- Host auth: Supabase email code (8 digits on this project) or link (`/login`, `/auth/confirm`). Email templates for Magic Link and Confirm signup live in the Supabase dashboard. `src/middleware.ts` refreshes sessions and guards `/dashboard`, `/new`, `/sheets/*`. Host reads/writes use the cookie-session client in `src/lib/supabase/server.ts` (RLS applies), never the secret key.
- Testing as a host without email: `npm run dev:login -- host@example.test 3000` prints a one-time local sign-in link (dev only). Add a full origin (e.g. `http://macbook-air.local:3000`) to get a link that works on a phone.
- Phone testing: use the Mac's `.local` name (e.g. `http://macbook-air.local:3000`), not its 192.168.x.x IP — Supabase won't redirect to raw private IPs, so sign-in links fall back to the Site URL. The `.local` origin must be in Supabase → Auth → URL Configuration → Redirect URLs, and `next.config.ts` `allowedDevOrigins` allows it in dev.
- Hosting: Vercel project `can-someone-bring` (live at https://cansomeonebring.com; `www` redirects there; domain bought via Vercel, DNS at Vercel), connected to GitHub `dmercier47/can-someone-bring` — every push to `main` deploys production. Production env vars come from the Supabase↔Vercel integration (same Supabase project as dev). Supabase Auth → URL Configuration must list any new domain (Site URL + `https://<domain>/**`).
- Run: `npm run dev` → http://localhost:3000. Check: `npx tsc --noEmit && npm run lint`.
- Don't run `npm run build` while the dev server is running: both use `.next/` and the build breaks the dev server (ENOENT on `_buildManifest`). Stop dev first, or restart it after.
